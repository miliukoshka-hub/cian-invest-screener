# Назначение навыка

Загружай этот навык, когда пользователь просит что-то изменить, проверить, запустить, задокументировать или опубликовать проект «Инвестиционный скринер ЦИАН». Навык даёт рабочую карту репозитория и воспроизводимые проверки, чтобы правки не ломали существующий функционал.

Сначала прочитай `AGENTS.md` в корне проекта — он задаёт роли, ограничения и методику. Для финансовых расчётов используй методику из `AGENTS.md` и правила этого навыка, для рыночных аналогов — субагента `market-researcher`, для поиска и скоринга — субагента `cian-parser`.

# 1. Жёсткие правила проекта

Соблюдай их при любой правке:

- **Только собственные средства.** Кредиты, ипотека, займы, рассрочки и платежи по ним не участвуют в расчётах и не упоминаются в интерфейсе, отчётах и документации. Ставки аренды, налога и ремонта — это обычные расходы, они учитываются.
- **Без спроса ничего не меняй и не удаляй.** Перед перезаписью или удалением существующего файла спроси подтверждение. Создание нового файла по явной просьбе допускается.
- **Только внутри папки проекта** `C:\Users\Admin\Desktop\ии\Агенты\Недвижимость`. Временные скрипты — в `C:\Users\Admin\AppData\Local\Temp\opencode`, после работы удаляй их.
- **Никаких внешних публикаций** без явного поручения. Обновление GitHub — только по прямой просьбе.
- **Видимый интерфейс — только на русском.** Не допускай английских слов и знака `?` в видимом тексте дашборда и калькулятора (в атрибутах и URL это допустимо).
- **Дашборд:** только объекты с внутренним баллом 9–10; сам балл не показывать; сортировка от более привлекательных к менее привлекательным.
- **Не показывать объекты с долями.** Фильтр этажа: любой / кроме первого / кроме первого и последнего.
- **Значения по умолчанию:** бюджет до 11 000 000 ₽ (для «Квартиры под флиппинг» — 12 000 000 ₽), ремонт 50 000 ₽/м², цикл флиппинга 3 месяца, годовая доходность флиппинга без реинвестирования.
- **Цоколь и полуподвал** снижают оценочную цену на 30%; обычный первый этаж только помечается на проверку.
- **Один объект = одна горизонтальная строка.** Таблица прокручивается по строкам и колонкам. Экспорт — настоящий `.xlsx` через `fflate` (не CSV, не `xlsx`/`exceljs`).
- **Шапка:** логотип слева вверху, рядом с ним «Подбор инвестиционных лотов». Удалены «Инвест-скринер недвижимости», «Москва и Московская область», «ЦИАН» в шапке, кнопки «Пересчитать» нет. В калькуляторе — «Инвестиционный анализ недвижимости», не «анализатор».
- **Стратегии:** `auto` (лучшая из трёх), `long` (долгосрочная аренда), `short` (посуточная аренда), `flip` (флиппинг). Рекомендация считается по выбранной стратегии; при `auto` — по лучшей.

# 3. Запуск и перезапуск сервиса

Порт по умолчанию **3456**, сервер слушает `127.0.0.1`; переопределяется переменной `PORT`.

```powershell
# Вариант 1: двойной клик по start-parser.bat (открывает дашборд и сервер)
# Вариант 2: вручную
& "C:\Users\Admin\AppData\Local\nodejs\node.exe" "C:\Users\Admin\Desktop\ии\Агенты\Недвижимость\parser\server.js"
# Вариант 3: из папки проекта
npm start
```

После запуска проверить:

```powershell
Invoke-WebRequest -Uri 'http://localhost:3456/api/latest-results' -UseBasicParsing
```

Дашборд: `http://localhost:3456/cian-parser-dashboard.html`. Калькулятор: `http://localhost:3456/investment-calculator.html`.

**Важно:** после изменений в `parser/*.js` сервер нужно перезапустить — Node держит модули в памяти. HTML-файлы подхватываются без перезапуска (достаточно `Ctrl+F5`).

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '*parser\server.js*' } | Select-Object ProcessId,CommandLine
Stop-Process -Id <PID> -Force
```

Перезапуск сервера — частичное изменение рабочего состояния; выполняй его как часть запрошенной задачи и сообщи пользователю.

Расширение загружается распакованным из `chrome-extension/cian-collector` через `chrome://extensions` → «Режим разработчика». После правки `popup.js` или `manifest.json` расширение нужно перезагрузить в браузере.

# 4. Как вносить изменения

1. **Сначала прочитай**
   - `AGENTS.md`, этот навык и.target-файл целиком или нужный фрагмент.
   - Найди все места, где используется меняемое понятие (`grep`/`Select-String`), чтобы не оставить рассинхрон.
2. **Дашборд** — один файл, код в IIFE. При добавлении поля фильтра/настройки обнови **все** точки:
   - HTML-элемент `<select>`/`<input>`;
   - `filters()` — если поле влияет на отбор;
   - `settings()` — если поле влияет на расчёт (например, `strategy`);
   - `enrich()` — локальный пересчёт при импорте HTML/оффлайн;
   - `calcData` — передача в калькулятор;
   - массив пресетов и массив применяемых ключей в обработчике `[data-preset]`;
   - `chrome-extension/cian-collector/popup.js` → `readDashboardSettings()`.
3. **Калькулятор** — функции глобальные (`calculate()`, `loadPreset()`, `renderSavedTable()`, `exportTableToCSV()`, `applyImportedObject()`). Вердикт и оценка считаются по `strategyChoice`; при `auto` выбирается лучшая стратегия. Новые поля добавляй и в возвращаемый объект `calculate()`, и в таблицу сравнения, и в CSV.
4. **Ядро скоринга** — `scoreInvestments(items, investorSettings)`. Внутренний `investScore` (отбор 9–10) должен оставаться стабильным и считаться по лучшей из трёх доходностей; выбранная стратегия меняет `bestStrategy`, `recommendedYield` и `recommendation`. Не обнуляй список лотов при выборе аренды.
5. **Сервер** — не перезаписывай `strategy` принудительно; бери `investorSettings.strategy` с fallback на `filters.analysisStrategy`, иначе `auto`.
6. **Расширение** — читает настройки из вкладки дашборда; новые поля дашборда обязательно дублируй в `readDashboardSettings()`.
7. **Документация** — после правки обнови `README.md`, а при изменении интерфейса ещё и `step-by-step-guide.md`; при изменении формул — правила в `AGENTS.md`, этот навык и шаблон отчёта.
8. **Отчитайся** коротко: что изменено, какие проверки прошли, новый коммит (если публиковали).

# 5. Проверки перед завершением

Выполняй все применимые проверки, даже если кажется, что правка тривиальна.

### Синтаксис

Временный скрипт в `%TEMP%\opencode\check-syntax.js`: прочитать HTML, регуляркой `/<script(?![^>]*\bsrc=)[^>]*>([\s\S]*?)<\/script>/gi` вытащить inline-скрипты и прогнать `new Function(code)`; для `.js` — `new Function(файл)` или `node --check`.

### Браузер

Через инструменты `browser` (или Playwright с установленным браузером) открыть обе страницы и проверить:

- дашборд: `.brand .brand-title` = «Подбор инвестиционных лотов», в `.intro` нет `h2`, `img.naturalWidth` логотипа = 150;
- есть строки в `#listingContent tbody tr`, таблица не пуста;
- в `document.body.innerText` нет `?`, нет `анализатор`, нет кредитных слов;
- в калькуляторе `h1` = «Инвестиционный анализ недвижимости»;
- смена `strategyChoice` меняет `verdictStrategy` и `verdictText` (текст начинается со «Стратегия «…»: …»), `auto` даёт «Рекомендация по лучшей стратегии»;
- пресеты дают нужные значения: `flip → flip`, `rent → long`, `metro → auto`.

### Логика и API

- `GET /api/latest-results` → `STATUS 200`, есть объекты.
- `POST /api/recalculate-latest` с `investorSettings.strategy: 'long'` → в ответе `bestStrategy` = «Долгосрочная аренда», а количество лотов не падает до нуля.
- Прямой вызов `scoreInvestments(getRealisticSampleListings(), { strategy })` для `auto/long/short/flip`: отбор `investScore >= 9` стабилен, `bestStrategy` и `recommendedYield` меняются.
- JSON в `data/*.json` валидны (`JSON.parse`).
- После правок `parser/*.js` сервер перезапущен, иначе проверка API бессмысленна.

# 7. Подготовка к публикации

Публикация — только по явному поручению пользователя.

- Публичный репозиторий: `https://github.com/miliukoshka-hub/cian-invest-screener`, ветка `main`.
- Локальный Git не установлен. `gh.exe`: `C:\Program Files\GitHub CLI\gh.exe`, получение токена: `& "C:\Program Files\GitHub CLI\gh.exe" auth token`. **Никогда не выводи токен в чат и не пиши его в файлы.**
- Порядок через GitHub REST API:
  1. `GET /repos/{repo}/git/ref/heads/main` → текущий SHA;
  2. `GET /repos/{repo}/git/commits/{sha}` → `base_tree`;
  3. для каждого изменённого файла `POST /git/blobs` (`content` base64, `encoding: base64`);
  4. `POST /git/trees` с `base_tree` и массивом `{path, mode:'100644', type:'blob', sha}`;
  5. `POST /git/commits` с сообщением на русском, `tree` и `parents:[старый sha]`;
  6. `PATCH /git/refs/heads/main` с новым SHA.
- После загрузки проверь `https://raw.githubusercontent.com/miliukoshka-hub/cian-invest-screener/main/<путь>` для ключевых файлов.
- В ответе укажи коммит, список файлов и результат raw-проверки.
- Временный скрипт публикации удали из `%TEMP%\opencode`.

# 8. Типовые проблемы

| Симптом | Причина | Лечение |
| --- | --- | --- |
| Дашборд не открывается | Сервер не запущен или занят порт 3456 | Запустить `start-parser.bat`, проверить порт |
| Старые цифры после правки | HTML закэширован браузером; `parser/*.js` загружены в память | `Ctrl+F5`; перезапустить сервер |
| Расширение не передаёт новое поле | Не обновлён `readDashboardSettings()` | Добавить поле в `popup.js`, перезагрузить расширение |
| Список лотов пуст после выбора стратегии | Стратегия случайно применена к внутреннему `investScore` | Вернуть отбор к max из трёх доходностей |
| В вердикте снова низкая оценка по аренде | Вердикт считается не по `strategyChoice` | Проверить `calculate()` и передачу `strategy` в `calcData` |
| Excel не открывается | Использован не `.xlsx`, а CSV/другая библиотека | `parser/excel-export.js` + `fflate` |
| Логотип не рисуется | Неверный MIME | `image/svg+xml; charset=utf-8` |
| Правки не видны на GitHub | Git не установлен, коммит не создан | REST API по шагам из раздела 7 |
